# 연구 계획

## 동기

Code Mode는 에이전트가 도구를 하나씩 호출하는 대신 API를 호출하는 코드를 작성해 샌드박스에서 실행하게 한다. 이 방식이 내세우는 이점 중 하나는 프라이버시다. 중간 데이터는 샌드박스에 머물고, 모델은 코드가 내놓은 결과만 본다.

그러나 무엇이 모델에게 넘어갈지는 에이전트가 작성한 `return`과 `console.log`가 정한다. 에이전트가 레코드 전체를 출력해 구조를 파악하는 습관이 있다면, 샌드박스의 경계가 있어도 노출은 줄지 않는다. 이 이점이 실제 에이전트 행동에서도 유지되는지는 아직 측정된 적이 없다.

## 연구 질문

| | 질문 |
| --- | --- |
| RQ1 | Code Mode 에이전트는 과제에 필요한 최소한보다 얼마나 많은 개인정보를 모델에게 노출하는가? |
| RQ2 | 노출은 탐색용 출력, 최종 반환값, 에러 메시지 중 주로 어디에서 발생하는가? |
| RQ3 | 최소 반환 지시와 스키마 제공은 노출을 얼마나 줄이는가? |

## 핵심 개념

샌드박스 안의 코드가 API에서 받아 온 개인정보를 접근, 실제로 모델 컨텍스트에 들어간 개인정보를 노출이라고 한다. 이 연구가 측정하는 것은 노출이며, 접근은 읽은 것 중 얼마를 내보냈는지 비교하는 데만 기록한다.

단위는 (레코드, 필드) 한 쌍이다. 같은 고객의 전화번호가 세 번 출력되어도 노출은 1개로 센다.

## 실험 구성

사람 참여자는 없다. 데이터, API, 샌드박스, 실행기, 채점기는 모두 JavaScript(Node 22)로 작성한다.

- 데이터: 가짜 고객 10명, 연락처 10명, 메일 10통. 필드마다 개인정보 여부와 민감 여부를 미리 정한다.
- 과제: 20개. 과제마다 정답에 꼭 필요한 (레코드, 필드) 목록을 미리 정하고, 이를 이상적 최소 노출 기준선으로 쓴다.
- 비교 대상
  - Code Mode (주 대상): `search`와 `execute` 두 도구, `node:vm` 샌드박스
  - 이상적 최소 노출 (기준선): 과제별 필요 목록
  - 일반 MCP: 엔드포인트마다 도구 하나, 응답 전체를 반환 (참고용)
  - 필드 선택 MCP: 같은 도구에 `fields` 인자 추가 (참고용)
- Code Mode 2×2 조건: 기본 / 최소 반환 지시 / 스키마 제공 / 둘 다
- 반복: 모델 1-2개, 조건마다 3회

## 측정

- 과제당 불필요한 개인정보 노출 수. 민감 정보는 따로 센다.
- 경로별 노출 비율: 탐색 출력(`console`), 반환값(`return`), 에러(`error`)
- 과제 성공률. 노출을 줄이는 과정에서 성공률이 떨어지는지 함께 본다.
